1. WHAT IS PROFOUND?
--------------------------------------------------------------------------------

ProFound is an HBS MBA student tool (currently in private beta) for matching
students with Harvard Business School faculty based on shared research interests.
The core use cases are:

  1. Faculty matching — an AI run (Claude Sonnet) reads the student's profile
     (interests, resume, LinkedIn) and the HBS faculty database, then returns a
     ranked list of faculty with match strength ratings (Strong / Good /
     Exploratory) and written rationale.

  2. Course matching — same AI pipeline but matches against the 2026–27 HBS
     elective course catalog instead of faculty directly.

  3. Case Study Idea Generator — given a specific student–faculty match, Claude
     generates HBS teaching case concepts the student and professor could
     co-develop, tailored to both parties' backgrounds.

  4. Email draft tool — Claude drafts a cold outreach email to a professor
     incorporating the student's saved case study ideas.

The target user is an HBS MBA student (MBA 2027 cohort). The builder/sole
developer is Caleb O'Brien (cobrien@mba2027.hbs.edu), who is also a user.


--------------------------------------------------------------------------------
2. TECH STACK
--------------------------------------------------------------------------------

Frontend:   React 19 + Vite, React Router v6, Tailwind CSS v4
Backend:    Supabase (PostgreSQL + Row-Level Security + Auth + Edge Functions)
AI:         Anthropic Claude claude-sonnet-4-5 via native fetch inside Supabase
            Edge Functions (Deno runtime)
Auth:       Google OAuth + email/password via Supabase Auth
Hosting:    Vite dev server locally; Supabase cloud for DB + functions

Key design constraints:
  - Edge functions must be deployed with --no-verify-jwt (Supabase Auth issues
    ES256 JWTs but the default gateway verifies HS256)
  - Rate limiting is enforced via event-log tables + UTC day count queries
    (not middleware), e.g. max 3 faculty match runs/day, 5 course match runs/day,
    10 email drafts/day
  - Google OAuth app is in "External" mode — test users must be manually added
    in Google Cloud Console

Brand token: --color-crimson: #A51C30 (HBS crimson), defined in src/index.css

5. DESIGN SYSTEM
--------------------------------------------------------------------------------

Typography: Inter only throughout (400/500/600/700). Instrument Serif is loaded
but not used in the UI (was trialed and removed).

Color rule (enforced): Crimson (#A51C30) is reserved for:
  - Primary action buttons
  - Active/selected states (nav underline, filter pills, bookmark filled)
  - Unit badge chips and left-border accents on match cards
  Secondary interactive elements (utility links, view-profile arrows, back links,
  select-all toggles) use gray (text-gray-500/700).

Component patterns:
  - Skeleton loading (animate-pulse) on Faculty browse + Dashboard sections
  - animate-fade-in (220ms ease-out, 6px Y drift) on every page root div
  - hover:-translate-y-0.5 + hover:shadow-md lift on all cards and list rows
  - Sticky filter bar at top-14 (below NavBar h-14) on Faculty page
  - AbortController cancel pattern on all AI generation flows
  - Optimistic UI updates on all save/unsave/delete operations

Strength tiers: Strong (green-700/white) / Good (green-100/green-800) /
Exploratory (green-50/green-600). Defined in src/lib/constants.js.

7. KNOWN LIMITATIONS / THINGS NOT ADDRESSED
--------------------------------------------------------------------------------

  - No automated tests of any kind (unit, integration, e2e)
  - No error boundary components — unhandled React errors will show a blank page
  - The faculty database is populated via a Python/Playwright scraper (not in
    active use during this session); data freshness is manual
  - Supabase free tier row limit (100 rows per query) affects any table fetch
    that doesn't paginate — faculty_tags and faculty_publications are fetched in
    full without pagination
  - The bio stripping heuristic (stripBioHeader in FacultyDetail.jsx) uses last-
    name pattern matching and can misfire on unusual name formats
  - Google OAuth is still in "External" mode (not published) — only manually
    added test users can sign in via Google
  - No mobile-specific testing was done; layout is responsive but untested on
    real devices
  - The course deduplication fix is client-side; the database still contains
    duplicate rows for some faculty courses

9. SUGGESTED CRITIQUE ANGLES
--------------------------------------------------------------------------------

The reviewer may find it useful to consider:

  CODE QUALITY
    - Are there remaining inconsistencies in the crimson color rule?
    - Is the listVisible fade pattern (useState + setTimeout) the right approach,
      or would a CSS-only solution or a library be cleaner?
    - Is the course deduplication logic (client-side, by title) robust enough, or
      should it be enforced at the database level with a unique constraint?
    - Are the two saved-state hooks (useSavedFaculty, useSavedCourses) too similar
      to not be abstracted into a single generic hook?

  ARCHITECTURE
    - Should the AI calls live in Supabase Edge Functions (Deno) or move to a
      Node.js backend? What are the tradeoffs given the current rate-limiting model?
    - Is Supabase the right long-term choice, or would a more traditional backend
      serve this use case better?
    - The app has no React context or global state store — all state is local or
      prop-drilled. Is this sustainable as the app grows?

  UX / PRODUCT
    - Is the three-step flow (profile → match → case ideas → email) clear to a
      new user, or does it require too much discovery?
    - Are the rate limits (3 faculty matches/day, 5 course matches/day) well-
      calibrated for the use case?
    - Does the "How it works" collapsible add value or create friction?

  SECURITY
    - Are there any obvious RLS (Row Level Security) gaps in the Supabase schema?
    - The service role key is used in scripts — is this handled safely?
    - Are the edge functions adequately validating user input before passing it
      to Claude?
